Lock order: existing lifecycle/UI/input permits remain owned by restart. New
readiness work does not acquire a protected target barrier or a new UI lock.
Clone the watermark before locking enrollment. Final synchronous order is
enrollment index -> bounded-route mutex -> target registry -> ScopePermit gate
check. The final closure does not reacquire index/registry/routes and performs
no await, CDP command, callback, recording hook or owner mutex acquisition.
Existing attached()/poison() use index before targets; reader publish_bounded
only enqueues under routes and does not acquire index. Reader debt observation
releases its own mutex before entering bounded routes. Thus no lock is retained
while waiting for an enrollment task that needs it.

Atomic boundary: received==applied and no pending enrollment must hold while the
same routes mutex blocks reader admission, with the registry mutex retaining
the exact healthy full inventory until successful result construction. An event
admitted after an earlier drain but before this boundary changes received and
forces another wait. Holding only an earlier snapshot/check is insufficient.
The watermark proves reader admission through this linearization point, never
renderer quiescence or that no event can arrive after publication. Genuinely
post-publication targets remain subject to ordinary fail-closed admission and
settlement. If they require a separate generic settlement repair, report that
boundary; do not silently broaden this patch.
