# Adapter and migration inventory

This inventory is based on e2e commit `97f453fbcfd99b73faa0177ba60e489df9625b86`. It describes implemented boundaries and the evidence still required; source compatibility is not a claim that a hosted account has been exercised.

The companion attaches to the same browser and exact page target reported by agent-browser. It does not run Playwright. Both CLI connections carry immutable initial target/context bindings and `--cdp-dedicated` before discovery or attachment. A browser-free handshake requires exact refs, pre-dispatch stale proof, uncertain-outcome handling and passive scoped CDP ownership; every daemon command checks the expected protocol contract. The companion alone owns browser-wide auto-attachment, Fetch/auth interception and pause/resume. Native attachment and the independent read-only trace session cannot take over those responsibilities. These bindings do not make a shared endpoint safe: real Chromium CI exposed that public CDP cannot provide the required first-popup interception while guaranteeing zero attachment or pause of unrelated targets. Shared-browser/provider parity is therefore unsupported, not a pending parity claim.

Every remote endpoint must exclusively belong to its current attempt for the full lease lifetime: no unrelated contexts, pages, clients, or users may share it. Setting `scope: 'attempt'` is an ownership assertion, not an isolation mechanism. The runtime retains its initial check for foreign browser contexts before accepting exclusive default-context ownership. That check cannot prove who owns pages in the default context or prevent a service from introducing another user later; the provisioner must uphold the dedicated-browser contract. Existing attempt-owned prepared pages are allowed. Local launches already provide a new browser process and profile per attempt.

Provider preparation or recording clients, even if they belong to the same attempt, must not retain competing process-wide locale or timezone overrides. Chromium can reject a second agent's override in a shared renderer. The adapter accepts only the two exact duplicate-override responses after this immutable configuration already succeeded on its connection; this relies on the provider condition, not independent renderer-identity proof. An initial conflict or any other protocol error still fails. Local launches have no provider-side competing emulation client. Prepared cookies, storage, and ordinary pages do not violate this condition.

The source basis for this boundary is Chromium's [`TargetHandler::ShouldThrottlePopups`](https://chromium.googlesource.com/chromium/src/+/refs/heads/main/content/browser/devtools/protocol/target_handler.cc), which returns the handler's browser-wide `auto_attach_` state, and [`ShouldWaitForDebuggerInWindowOpen`](https://chromium.googlesource.com/chromium/src/+/refs/heads/main/content/browser/devtools/devtools_instrumentation.cc), which consults browser-agent-host target handlers. The public [`Target.autoAttachRelated` command](https://chromedevtools.github.io/devtools-protocol/tot/Target/#method-autoAttachRelated) is not equivalent to that browser-wide popup throttle. Together with the real Chromium failure, these sources motivate this adapter's dedicated-only policy; narrower target discovery does not establish the required shared-browser safety guarantee. Within a dedicated browser, the companion can enable browser-wide attachment while retaining exact context checks before installing hooks or applying attempt state.

Remote file downloads require the provider's `downloads` transfer hook. Without it, the fixture refuses before triggering the download; it never mistakes a remote path for a local file. Provider recordings are unredacted artifacts with the same explicitly incomplete-redaction policy as the original Web engine.

### Callback connection compatibility

`connect.cdpEndpoint(signal)` returns a dedicated Chromium CDP HTTP discovery or WebSocket endpoint. Specify `scope: 'attempt'`; the single-callback shape without a scope defaults to worker scope and is rejected synchronously. It is mutually exclusive with a browser provider and local launch configuration. The engine detaches its connections and cleans up only the context/pages it owns; a callback-supplied endpoint does not authorize terminating the remote browser.

The two-callback shape is retained for source compatibility with the old engine's attempt-provisioning form, but its recovery behavior deliberately changes: `reconnectEndpoint` is never called, whether a read, input, or disconnect fails. The original endpoint is reused only inside the same explicit attempt lifecycle. The provisioner must supply an exclusive browser for each new attempt; it must not return another user's browser, retain unrelated pages, or allow concurrent users or clients. Explicit `scope: 'worker'` always fails preflight, even when the legacy reconnect callback is present. A new attempt can call `cdpEndpoint` again, but this is provisioning a new attempt rather than retrying an uncertain action.

Endpoint callbacks have a bounded initial resolution budget and receive cancellation. A callback that ignores cancellation cannot install a late endpoint into a later attempt. Errors never include callback exception text, returned endpoint credentials, or provider diagnostics. Raw callback connections provide no remote-file transfer hook, so `browser.waitForDownload` is explicitly unavailable; use a browser provider with `downloads` when remote downloads are required.

## Other packages

- `@e2e-dev/mobile` remains the independent agent-device engine. Native iOS/Android app declarations are rejected by this Web engine.
- `@e2e-dev/limrun`, `@e2e-dev/testmu`, and `@e2e-dev/eas` implement the device-provider contract, not the browser-provider contract. They continue to use the mobile engine unchanged.
- `@e2e-dev/github` consumes runner reports and remains unchanged. No GitHub write or credential is required by the adapter's fixture workflow.
- `@e2e-dev/decision` and shared runner/model packages remain unchanged. The engine implements the public SPI rather than importing a Web-engine implementation or adding core-to-engine dependencies.

## Deliberate security and behavior changes

- Basic authentication defaults to the configured app site. `basicAuth.scope: 'any-origin'` explicitly opts into the original engine's broader server-challenge behavior. Proxy challenges and mismatched challenge origins are never answered.
- Protected header values may be declared `Secret` values and are resolved through the attempt's redaction ledger. No protected value is placed in CLI arguments or state files.
- Screenshot attestation verifies the decoded PNG bytes for every visible masked field rectangle, as well as source DOM/frame geometry. It refuses pixels for transformed/perspective/zoomed frame-owner chains, non-integral or mismatched frame viewport mapping, unsupported PNG formats, over 16,777,216 pixels, or over 4,096 required regions. These are explicit fail-closed screenshot limits, not silently unmasked fallbacks. Sensitive-input taint continues to suppress screenshots entirely.
- Pixel observations complete screenshot proof and cleanup before refreshing semantic references. A rejected screenshot does not replace the last published references; exact-node checks and normal observation invalidation still apply. Browser identity changes or sensitive-input taint during the operation discard its result. The image and semantic tree are sequential observations, not an atomic capture of an asynchronously changing page.
- An uninstantiated `OBJECT` remains in the exact DOM inventory. It is accepted only while a connected owner or a shadow-including ancestor has `display:none`, verified during stabilization and before/after capture. Opacity, visibility, MIME declarations and empty bounds are not exemptions. Fractional content sizes must match Chromium's exact integer viewport rounding; any source-sensitive rectangle in that fractional subtree, including from a nested document, still fails closed. Empty auxiliary documents remain fully inspected, not skipped.
- HTML `OBJECT` child documents use the same complete frame inventory, content-box projection, pre/post checks, mask installation and PNG proof as `IFRAME`/`FRAME`. The child must report `text/html` and exactly match the owner's content viewport, including border and padding offsets. PDF, plugin, `EMBED`, SVG/XML object documents and other unproven owner types are explicitly refused, not skipped. Diagnostic reasons identify unsupported owner types/documents, transformed owners and viewport mismatches without including page text.
- Exact-node `fill` preserves the browser editing path after actionability validation. Text controls use the upstream clear followed by trusted insertion; contenteditable uses a DOM Range selection followed by browser insertion or deletion. Native value setters remain only for validated date/time-family inputs and emit synthetic input/change events. `keyboard.type` explicitly requests `--physical`, emitting trusted keydown/up for mapped characters and browser text insertion for unmapped Unicode. Ordinary native `keyboard type` keeps the upstream insertion behavior. Engine/cache epoch 6 rejects prior epoch-5 synthetic-fill recordings.
- Node and coordinate swipes use trusted CDP wheel input with the original engine's direction and momentum distances; element swipes target the element center after exact-ref hover.
- Concurrent UI input sequences are rejected rather than serialized behind waits. Network waits, asynchronous route handlers, response delivery, and diagnostics remain independent of the UI-command path.
- Route, dialog, and download-trigger continuations retain their originating browser generation and invocation lifetime. Once a callback completes or expires, it cannot obtain a new fixture operation even if the browser generation is unchanged. This does not cancel or undo browser commands that were already dispatched.
- The factory's cache identity is `agent-browser-exact-6`; synthetic-fill epoch 5 recordings are not replayed. The runner keys by engine name and SPI, not package version. Incompatible semantic changes require a new identity epoch.
- Stock agent-browser is refused. The maintained public CLI extension supplies strict refs and several necessary semantic safeguards; upgrading only the npm executable is not supported.

## Remaining proof

A passing unit suite is insufficient. The exact published commit must pass native Rust tests and all mandatory real Chromium integration files. Hosted service accounts and the user's private preproduction application require separate authorized UAT. No private application source, address, account, or credential is included in these fixtures.

## Ordinary baseline and macOS external-attachment limitation

The ordinary-behavior comparison uses the same CLI-owned Chromium lifecycle for the unmodified official executable and the maintained executable: identical pinned Chromium, isolated configuration/session, public `get cdp-url`, then a read-only observer. The ordinary UI/event assertions remain unchanged. This comparison does not establish arbitrary unscoped external-CDP compatibility.

A separate investigation at e2e commit `7e23a28bf61c0d457dbf13975764abc927d7e053` reproduced a macOS navigation hang in **both** official source `5ee8691339a5a002e4d7454eec95250253bc7419` and maintained source `e1b6063839e5e33f556713655b296a2dc0ff5ca3` when attaching an ordinary, unscoped CLI to an already running browser. In the [ARM64 method trace](https://github.com/levicode/e2e/actions/runs/39397602229/job/118544090986), startup and the first 16 CDP commands replied successfully; `Page.navigate` was sent without a reply before the unchanged 30-second command deadline. A separate renderer probe also failed within two seconds, with no proxy forwarding error. The earlier [ARM64](https://github.com/levicode/e2e/actions/runs/39388109623/job/118513117341) and [Intel](https://github.com/levicode/e2e/actions/runs/39388109623/job/118513117174) runs exposed the same first-navigation timeout before method tracing was added. The precise upstream/browser cause is not established, and this migration does not claim to fix that ordinary external-attachment path.

The supported e2e path is different and remains a mandatory gate: the harness owns the dedicated browser, its CDP companion owns lifecycle pause/resume, and native clients use immutable target/context scope with passive attachment. Actual native actions, locators, runner/replay and fresh installed-consumer tests cover that path on each supported architecture. A passing owned-browser comparison must never be presented as resolving the known unscoped external-attachment limitation. Preserve the failing run evidence when reporting platform support.

Model observations and tool targets preserve native `@eN` references. The adapter supplies the canonical reference explicitly; it never recovers it by stripping an opaque ID. Internal UUID, observation generation, and instance scope remain in dispatch state. Structural roots and unreferenced text remain visible without invented action references. Explicit browser reset, restore, and restart create a new instance scope; ordinary observations retain their native reference spelling.
